# 01 · 硬件诊断与结论

## 1. 问题起点

用户报修：黑苹果无声，认为是「SN6180 声卡」，希望从 Linux 开源驱动移植成 kext。

## 2. 实测诊断过程

### 2.1 系统层面

```bash
system_profiler SPAudioDataType       # Devices 列表为空 —— 系统没有任何音频设备
kextstat | grep -i -E 'audio|hda'     # AppleHDA / AppleHDAController / IOHDAFamily 均已加载
```

关键矛盾：**AppleHDA 驱动栈已加载，但没有任何音频设备出现**。说明控制器被识别了，但 codec 没有匹配到驱动。

### 2.2 IORegistry 读取真实 codec ID

```bash
ioreg -r -c IOHDACodecDevice -l
```

读到：

```
IOHDACodecVendorID   = 351346567
IOHDACodecRevisionID = 1048832
```

精确换算（心算易错，必须用工具）：

| 十进制 | 十六进制 | 含义 |
|---|---|---|
| 351346567 | `0x14F11F87` | **本机 codec = SN6140** |
| 1048832 | `0x100100` | revision |
| 351346897 | `0x14F120D1` | SN6180（**不是本机**） |

> ⚠️ 过程中曾一度心算误判为 SN6180，后经 Python 精确换算纠正。**硬件以 IORegistry 实测为准。**

### 2.3 根因确认

```
IOHDACodecFunction 下已生成 AppleHDACodecGeneric / AppleHDADriver
但状态为 !registered, !matched
```

- AppleHDA 二进制内**不含** SN6140 的配置
- 官方 AppleALC 支持的 111 个 codec 家族里**没有** SN6140/SN6180
- 引导参数里原本 `alcid=11`，但 AppleALC 不认识这颗 codec，注入无效

**结论**：codec 硬件在，但没有任何驱动配置匹配它 → 无声。

## 3. 芯片身份对照

| 型号 | Vendor:Device ID | 备注 |
|---|---|---|
| **SN6140** | `14f1:1f87` | **本机实测**，Senarytech/Connexant 家族 |
| SN6180 | `14f1:20d1` | 用户最初以为的型号，非本机 |
| SN6186 | `1fa8:6186` | Linux 主线 `senarytech.c` 里的型号，非本机 |

三者同属 Conexant(`0x14f1`)/Senarytech(`0x1fa8`) 家族，Linux 里由 `patch_conexant.c` / `senarytech.c` 处理，但 **pin 配置各不相同，不能混用**。

## 4. 诊断结论

1. 本机真实芯片是 **SN6140**（`0x14F11F87`），不是 SN6180。
2. 故障性质是「**配置缺失**」而非「硬件不识别」——不需要从零写驱动，只需给 AppleHDA 一份正确的 layout 配置。
3. 社区已有同款 codec + 同款 macOS 15.8.1 的验证方案（layout 15），可直接采用，避免从零构造 verb 数据的高风险。
