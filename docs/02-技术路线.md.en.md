# 02 · Technical Approach: Why AppleALC Injection

> English version of [02-技术路线.md](02-技术路线.md).

## 1. Comparison of Three Possible Routes

| Route | Approach | Assessment |
|---|---|---|
| **A. AppleALC configuration injection** ✅ adopted | Extract SN6140 verb/pin/layout config from Linux driver/community, turn it into layout data AppleALC understands, reuse native AppleHDA | Sound quality, sleep/wake, volume control all native; community-verified; most robust |
| B. VoodooHDA-style code port | Actually port ALSA HDA C code into a standalone kext | Requires rewriting the whole audio stack (verbs/DMA/PCI), conflicts with AppleHDA; poor macOS 15 support; worse sound |
| C. Write a standalone kext from scratch | Implement controller + codec on IOAudioFamily / AudioDriverKit | High academic value, low practical value, very long cycle; IOAudioFamily deprecated in macOS 15, Apple moved to user-space AudioDriverKit |

## 2. Why Not Port the Linux ALSA Code Directly

- ALSA's HDA driver depends on the entire Linux kernel audio stack (`snd_hda_core`, verbs, DMA, PCI). Porting it wholesale means writing an audio stack that runs in parallel with — and conflicts with — AppleHDA.
- VoodooHDA took this route, but support for Sequoia is poor.
- `IOAudioFamily` is deprecated in macOS 15; Apple moved to user-space AudioDriverKit, so the technical window for writing a kext from scratch has closed.

**The only viable "port" is porting configuration data, not C code.**

## 3. How the AppleALC Injection Works

```
OpenCore boots
   │
   ├─ Kernel>Add injects Lilu.kext (patch engine, must come before AppleALC)
   ├─ Kernel>Add injects custom AppleALC.kext (contains SN6140 layout 15 resources)
   ├─ NVRAM boot-args: alcid=15 alcdelay=1000
   └─ DeviceProperties: HDEF layout-id / alc-layout-id = 15
                    │
                    ▼
AppleALC hooks AppleHDA, feeds layout 15 verb/pin config to the native driver
                    │
                    ▼
AppleHDADriver successfully matches SN6140 → speakers / headphones output sound
```

Why layout 15: the community (`chenhggu6475/Senary-SN6140-AppleALC-Hackintosh`) verified on the same `14f1:1f87` rev `0x100100` and same macOS 15.8.1 that `layout 15` enables internal speakers and headphone audio output. The configuration resources are at [../01-driver/source/Resources/SN6140/](../01-driver/source/Resources/SN6140/).

> This version covers **output only**. Microphone input ports are not customized; System Settings → Sound → Input keeps the default device. See [Scope of This Version in the README](../README.md.en.md).

## 4. Concrete Actions Taken in This Project

1. **Replace the kext**: official AppleALC 1.9.8 (no SN6140) → custom 1.9.9 (`DBG-199-2026-10-26`, binary contains SN6140 data).
2. **Change boot-args**: `alcid=11` → `alcid=15`, add `alcdelay=1000` (leaves time for codec initialization).
3. **Change layout-id**: HDEF `layout-id` / `alc-layout-id` from int 11 → data 15.
4. **Disable conflicting kext**: `SimpleHDA.kext` fights AppleALC for the same HDA controller, must be off.
5. **Ensure ordering**: `Lilu.kext` must come before `AppleALC.kext`.

Every step is automated by [../02-efi-oc/deploy_sn6140.py](../02-efi-oc/deploy_sn6140.py), with backup/rollback. See [03-OpenCore配置说明.md.en.md](03-OpenCore配置说明.md.en.md).
