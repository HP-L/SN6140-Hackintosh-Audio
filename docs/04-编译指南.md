## 2. 资源打包流程（已执行）

```bash
# 1) 编译资源转换工具（Objective-C++，需 Foundation/Cocoa）
clang++ -ObjC++ -std=c++14 -fobjc-arc -mmacosx-version-min=10.12 \
  ResourceConverter/main.mm -framework Foundation -framework Cocoa -o ResourceConverter_bin

# 2) 把所有 xml 压成 .zlib（Tools/zlib.pl deflate，共 1310 个资源）
perl Tools/zlib.pl deflate Resources/SN6140/layout15.xml > Resources/SN6140/layout15.xml.zlib

# 3) 生成内嵌资源的 C++ 文件
./ResourceConverter_bin Resources AppleALC/kern_resources.cpp
```

生成结果确认含 SN6140：`0x1F87` vendor device ID、layout 15/16/17 资源。

## 3. 编译参数（关键，踩坑所得）

```bash
clang++ -c -arch x86_64 -target x86_64-apple-macosx10.9 \
  -std=c++14 -fno-exceptions -fno-rtti -fno-builtin \
  -fapple-kext -nostdinc -isystem MacKernelSDK/Headers \
  -I Lilu.kext/Contents/Resources -I AppleALC \
  -I AppleALC/ALCUserClient -I AppleALC/ALCUserClientProvider \
  -DKERNEL=1 -DPRODUCT_NAME=AppleALC -DMODULE_VERSION=1.9.9 -DHAVE_ANALOG_AUDIO=1 \
  AppleALC/kern_xxx.cpp -o build_objs/kern_xxx.o
```

几个必须注意的点：

- `-fapple-kext`：kext 编译模式；`-nostdinc -isystem MacKernelSDK/Headers`：只用内核头，排除系统 SDK 干扰。
- `-DKERNEL=1`：Xcode 会自动定义，命令行必须手动加，否则 `IOPCIDevice` 类定义被跳过。
- Lilu 的 `hde64.h` / `capstone` 是指向 `Contents/hde/`、`Contents/capstone/` 的符号链接，这些目标目录必须补齐，否则头文件解析失败。
- MacKernelSDK 新版 `IOPCIDevice.h` 在 `TARGET_OS_OSX` 时会 include PCIDriverKit 版本并与自身形成循环，本地构建副本里把该 `#if` 改为 `#if 0` 绕过（仅本地构建，不改系统）。
- zsh 下变量不分词，`build.sh` 用 bash 数组（`CF=(...)`）规避。

运行全部编译：

```bash
cd 01-driver/source && bash build.sh
```

**链接失败原因**：本机只有 Command Line Tools（clang 17 / ld 1167），没有完整 Xcode。社区产物是用完整 Xcode 16.4（clang 15 工具链）编译的。这是工具链版本差异导致的 linker 内部断言，属于环境限制，不是源码问题。

## 5. 完整编译的建议做法

1. 安装**完整 Xcode 16.4**（含对应 SDK 与链接器）。
2. 打开 `01-driver/source/AppleALC.xcodeproj`，选目标 kext scheme，`Cmd+B` 编译（Xcode 工程已配置好 `KERNEL_EXTENSION_HEADER_SEARCH_PATHS` 等，能正确处理 SDK/DriverKit 头）。
3. 或使用匹配版本的 clang/ld 运行 `build.sh`。
