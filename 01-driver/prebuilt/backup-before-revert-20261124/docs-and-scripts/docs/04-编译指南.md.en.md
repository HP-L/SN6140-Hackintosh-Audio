# 04 · Build Guide (Source-Level Reproduction)

> English version of [04-编译指南.md](04-编译指南.md).

This project retains the complete AppleALC source snapshot and dependencies, so compilation is reproducible in principle. This page records the actual build process, completed stages, and the final limitation.

## 1. Source Project Structure (01-driver/source/)

| Path | Role |
|---|---|
| `AppleALC/*.cpp` | AppleALC core sources (kern_start / kern_alc / kern_resources + two UserClients) |
| `AppleALC/kern_resources.cpp` | **Already generated**, embeds all codec resources (~10 MB, includes SN6140) |

## 2. Resource Packing Process (Already Executed)

```bash
# 1) Compile the resource converter (Objective-C++, needs Foundation/Cocoa)
clang++ -ObjC++ -std=c++14 -fobjc-arc -mmacosx-version-min=10.12 \
  ResourceConverter/main.mm -framework Foundation -framework Cocoa -o ResourceConverter_bin

# 2) Compress all xml into .zlib (Tools/zlib.pl deflate, 1310 resources total)
perl Tools/zlib.pl deflate Resources/SN6140/layout15.xml > Resources/SN6140/layout15.xml.zlib

# 3) Generate the C++ file with embedded resources
./ResourceConverter_bin Resources AppleALC/kern_resources.cpp
```

The generated result confirmed to contain SN6140: `0x1F87` vendor device ID, layout 15/16/17 resources.

## 3. Build Flags (Critical, Learned the Hard Way)

```bash
clang++ -c -arch x86_64 -target x86_64-apple-macosx10.9 \
  -std=c++14 -fno-exceptions -fno-rtti -fno-builtin \
  -fapple-kext -nostdinc -isystem MacKernelSDK/Headers \
  -I Lilu.kext/Contents/Resources -I AppleALC \
  -I AppleALC/ALCUserClient -I AppleALC/ALCUserClientProvider \
  -DKERNEL=1 -DPRODUCT_NAME=AppleALC -DMODULE_VERSION=1.9.9 -DHAVE_ANALOG_AUDIO=1 \
  AppleALC/kern_xxx.cpp -o build_objs/kern_xxx.o
```

Points to note:

- `-fapple-kext`: kext compilation mode; `-nostdinc -isystem MacKernelSDK/Headers`: use only kernel headers, excluding system SDK interference.
- `-DKERNEL=1`: Xcode defines this automatically; on the command line it must be added manually, otherwise the `IOPCIDevice` class definition is skipped.
- Lilu's `hde64.h` / `capstone` are symlinks to `Contents/hde/` and `Contents/capstone/`; those target directories must be present or header resolution fails.
- Newer MacKernelSDK's `IOPCIDevice.h` includes the PCIDriverKit version when `TARGET_OS_OSX` and forms a circular include with itself; in the local build copy change that `#if` to `#if 0` to work around it (local build only, do not touch the system).
- zsh does not word-split variables; `build.sh` uses bash arrays (`CF=(...)`) to avoid this.

Run the full build:

```bash
cd 01-driver/source && bash build.sh
```

## 4. Current Progress and Limitations

| Stage | Status |
|---|---|
| ResourceConverter compilation | ✅ success |
| zlib compression of 1310 resources | ✅ complete |
| kern_resources.cpp generation (with SN6140) | ✅ success |
| Compilation of 9 object files | ✅ all success |
| Final kext binary link | ❌ local linker triggers `LinkEditClassic` assertion crash |

**Reason for link failure**: this machine only has Command Line Tools (clang 17 / ld 1167), not full Xcode. The community artifact was built with full Xcode 16.4 (clang 15 toolchain). This is a linker internal assertion caused by toolchain version differences — an environment limitation, not a source problem.

## 5. Recommended Way to Build Fully

1. Install **full Xcode 16.4** (with matching SDK and linker).
2. Open `01-driver/source/AppleALC.xcodeproj`, select the target kext scheme, build with `Cmd+B` (the Xcode project has `KERNEL_EXTENSION_HEADER_SEARCH_PATHS` etc. configured, so SDK/DriverKit headers are handled correctly).
3. Or run `build.sh` with a matching clang/ld version.
